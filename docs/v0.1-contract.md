# pi-scopes experimental v0.1 contract

Status: implementation contract for the experimental package, including opt-in Docker-copy execution.

Pi dependency: `@earendil-works/pi-coding-agent@0.85.1`.

Parent and child sessions run in the same process. Goals use the SDK prompt API, results use the local `scope_return` callback, and cancellation uses an abort signal; no socket transport or intercom dependency is required.

Supported hosts: Linux and macOS.

## Purpose

v0.1 tests one claim: a same-model child with isolated conversation context can do noisy investigation and return a bounded result capsule that helps the parent finish a task.

The Docker checks exercise a concrete command-execution boundary. They do not establish general sandbox security, runtime-exploit resistance, unattended crash-time containment, parallel/recursive delegation or comparative model effectiveness.

## Observable behavior

1. The extension registers `scope` without replacing existing parent tools, model, thinking level, workspace, or conversation when unused.
2. The model starts a foreground child with `scope({ action: "run", context: "fresh" | "fork", goal, maxTurns? })`. Context defaults to fresh. The old action `fork` is rejected; there is no compatibility alias. Both modes are available per invocation.
3. The child inherits the parent's model and thinking level in a separate in-memory session. Fresh mode receives a self-contained goal and optional project guidance; fork mode receives the active conversation snapshot and effective parent instructions. Neither inherits extension runtimes or permission hooks.
4. The child sees only the explicitly selected built-in tools plus `scope_return`.
5. Owner environment selects `host-shared` (default) or `docker-copy`. Context fresh/fork does not select authority. Host mode is unrestricted; Docker work tools run only against an isolated copy.
6. Host mode receives private scratch and scope environment variables. Docker mode has guest `/workspace` and `/tmp`; host environment variables and mounts are not forwarded.
7. The child must normally finish by calling `scope_return` with a structured result capsule and outcome `complete` or `partial`. Partial means the investigation is incomplete, not that structured return failed.
8. If the child ends without `scope_return`, the harness returns a partial capsule containing its final text and an explicit fallback reason.
9. The parent receives the capsule, including supplied evidence, artifact references, decisions, and confidence, not the child transcript.
10. The full child event trace remains on local disk and can be inspected with `/scope open`, `/scope result`, and `/scope traces`.
11. Cancelling the parent tool call aborts the child session and marks the scope cancelled.
12. Completed scope records remain inspectable after their runtime and scratch resources are disposed.

## Starting context and project guidance

**Fresh delegation** (default): provide the concrete question/reproduction, constraints, and expected evidence in `goal`. No parent conversation is copied. `repoInstructions` defaults to true; false explicitly disables project guidance for fresh runs.

Project guidance is selected from the nearest `.git` root through the starting cwd, or cwd alone when no Git root is found. Each directory uses Pi 0.85.1 precedence: `AGENTS.override.md`, `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`, `CLAUDE.MD` (first file only). No global agent-directory or outside-project ancestor files are discovered. Canonical paths keep selected symlinks inside the project. Selected unreadable/dangling or outside-project guidance fails explicitly; a 32,000 UTF-8 byte aggregate ceiling rejects oversized guidance before inference instead of truncating it. No matching file means no guidance, recorded with an empty source list. This narrow selector is intentional because Pi's general loader also discovers global/ancestor files and logs-and-skips read failures.

**Forked context**: snapshot only the active parent branch **before the assistant message containing the current run call**. The invoking tool batch is excluded, including any sibling results, to avoid unfinished call/result pairs. Compaction/branch summaries on that branch retain their native SDK semantics. Later parent updates are not copied. The snapshot is deep-cloned into a child session; parent state and sibling branches are untouched.

Fork also inherits the effective parent system prompt, with an explicit current-child assignment overriding parent orchestration instructions. Project guidance is not loaded again; `repoInstructions` is rejected for fork mode because inherited instructions cannot be selectively removed by that switch. Inherited textual skills/global guidance may therefore remain in fork context; their extension runtimes, tool implementations and permission hooks are not copied. The supplied child tools remain authoritative. This is not a byte-identical provider request or inherited authority.

Both modes retain the same bounded investigation, return-only phase, cancellation and evidence-retrieval behavior. New scopes/capsules record the context mode. `scope.context` trace metadata records guidance source paths or the fork's parent session/entry boundary. Existing stored records without mode metadata remain readable. Children are told to check more-specific guidance when exploring nested directories; this is behavioral guidance, not access control.

## Docker-copy execution

Owner configuration: `PI_SCOPES_EXECUTION=docker` and `PI_SCOPES_DOCKER_IMAGE=sha256:<complete local image ID>`. Host is the default; unknown execution values, missing/mutable image IDs, failed provisioning or unavailable Docker fail explicitly. No automatic image pull/build, installation or host fallback. This policy is not a model-facing tool argument. Images and Docker infrastructure are trusted prerequisites; images need Bash, GNU tar and GNU find, without declared volumes. Dependencies can be prepared in the image or installed project-locally with owner-enabled networking. See the [equipped image recipe and owner settings](../docker/README.md).

**Input:** a clean committed Git snapshot, at most 12 MiB and 10,000 regular files. Git object export does not apply filters/export attributes. The index and literal working-file bytes must match the commit; non-ignored untracked files, deleted/modified files, executable-mode differences, symlinks and submodules are refused rather than silently omitted. Working copies requiring CRLF/smudge transformations may therefore be refused despite Git reporting clean. Ignored files and Git administration are not copied. Nested cwd, including an empty starting directory, maps under `/workspace`. Source revision is recorded in scope/capsule metadata and trace. Concurrent host edits after snapshot capture are not live updates.

Git plumbing disables fsmonitor hooks/lazy fetch and avoids `git status`/working-file diff, which can execute clean filters. A private regular-file copy is archived with host tar and streamed into the unprivileged guest; nothing is extracted back onto the host. Files selected for import are an explicit disclosure: committed secrets, guidance and inherited fork text are not redacted. Local host code, owner configuration, the model provider and Docker itself remain trusted.

**Work:** a fresh container with no host mounts/socket/PID sharing; user 65534, read-only rootfs, dropped capabilities, no-new-privileges and no IPC. Network defaults to none; owner-selected bridge permits host/LAN/Internet reachability, not domain-filtered access. Defaults are 2 CPUs, 2 GiB memory, 256 PIDs and executable 1 GiB tmpfs each for `/workspace` and `/tmp`; owner settings can adjust these. Effective policy and on-PATH tool availability are recorded and surfaced to parent/child. Availability is not version or project compatibility verification. Only isolated `bash` and `scope_return` are active. File/search/edit commands go through Bash inside Docker. Other tool names are unavailable, including host file tools. Inference/auth/session machinery remains on the host, not in the guest. The image's contents are trusted; pinning prevents tag drift, not malicious image behavior or runtime/kernel exploits.

**Output:** custom Bash captures at most 1 MiB per command and 8 MiB per scope directly into owner-only evidence blobs; it does not invoke the SDK's host-temp-file accumulator. Results display a bounded tail plus exit status. A nonzero command exit is returned as data, not a passing-test claim; execution failures carry explicit metadata and stop further work. Evidence inspection preserves both status and raw captured output after runtime/scratch removal, including failed commands. These output limits do not cap all trace/model-record memory or spending. No arbitrary guest-file export or automatic patch promotion. A bounded workspace text patch is captured automatically before disposal (see Automatic patch capture below); other needed evidence must be printed as command output. Guest artifact references alone do not preserve files.

**Lifecycle:** scope timeout/cancellation covers setup, inference and work. Work-command abort/timeout/output overflow kills the host Docker client and removes/verifies the whole container. Import's host archive process and Docker client receive cancellation, followed by outer runtime cleanup. Creation/start/control calls have bounded individual deadlines and cancellation checkpoints; this is not an instantaneous deadline for unresponsive daemon operations. A total scope abort prevents further inference/return prompting.

Container identity is recorded before creation. Normal return waits for cleanup; failure to verify cleanup is stored as `cleanup-failed`, returns failure and blocks further launches in that session. Restore Docker and reload/reopen the session to reconcile saved identities; only matching labelled runtimes are removed. Reopen finalizes interrupted work rather than resuming it. There is no independent watchdog: parent crash or ambiguous daemon failure may leave a runtime until reconciliation, and absence checks describe the daemon state observed at that time. This mode is not certified for unattended hostile workloads.

## Limits

- Maximum depth: 1.
- Maximum active children: 1.
- Execution: foreground only.
- Workspace: owner-selected host-shared or docker-copy; one mode per invocation captured from owner environment.
- Investigation allowance: `maxTurns` is an integer from 1 to 50, default 8. At the completed-turn boundary the harness stops investigation and, if not externally cancelled, prompts the same child with only `scope_return` enabled. At most two return turns are allowed, including any validation repair. Attempts to call work tools in this phase do not execute them. The default is provisional, not benchmark-tuned.
- A turn includes an assistant response and its tool calls; multiple commands and large outputs can occur in one turn. This is not a tool-call, token, or cost cap. Provider retry/compaction work is not an investigation turn. Combined usage still includes return inference. Parent budget is not automatically reserved.
- Scope limits: the total wall-clock timeout includes both phases and signals cancellation; it is not a process-kill deadline for uncooperative setup or I/O. Parent cancellation or timeout prevents further return prompting and may leave no useful summary. Token and cost usage are measured but not pre-emptively enforced.
- Child usage is returned as Pi-native nested tool usage and included in parent session totals. It counts newly generated persisted assistant history, compaction/branch-summary calls, and nested tool usage. Entries copied from parent history are excluded: historical usage is not charged twice. Provider-reported input/cache usage for processing that inherited context is still counted. Each returned capsule with measured usage retains it in `usage` (Pi's `Usage` fields plus `turns`).
- The child does not inherit parent permission extensions. Host mode's Bash is unrestricted; Docker mode withholds host tools. Loaded/inherited instructions are not access controls.
- Trace storage: local plaintext with owner-only directory permissions. Secret redaction is not promised in v0.1.
- Session replacement (`/new`, `/resume`, `/fork`), `/reload`, and shutdown cancel any active child. Completed scopes remain in the trace store.
- Crash recovery: interrupted children are finalized as failed; Docker identities are reconciled on reopen when possible. Cleanup failures remain explicit; no orphan inference is resumed.

## Terminal scope states

- `completed`: a valid `scope_return` capsule was captured.
- `partial`: the child explicitly returned incomplete findings, or finished without a valid capsule but recoverable output exists. Only fallback output has a `fallbackReason`.
- `failed`: creation, execution, trace persistence, or capsule validation failed.
- `cancelled`: an abort signal stopped the child.

Runtime disposal is recorded separately and is not a scope state. `cleanup-failed` means runtime teardown was not verified; it is never relabelled disposed merely because inference ended.

## Result capsule

The required fields are:

- `status`: `completed`, `partial`, `failed`, or `cancelled`;
- `summary`: at most 8,000 characters;
- `traceRef`: assigned by the harness.

Optional semantic fields are conclusions, evidence, artifacts, decisions, unresolved questions, and confidence. The harness validates these fields but never invents missing findings.

The combined semantic fields must fit within **16,000 UTF-8 bytes** when serialized as compact JSON (excluding the `outcome` control field and harness metadata). Oversized structured returns are rejected with an instruction to shorten and retry; findings are not silently dropped to satisfy the aggregate limit.

Parent-facing and `/scope result` text is also capped at **16,000 UTF-8 bytes**, including its trace reference. Formatting overhead, legacy results, or fallback text may require display truncation; an explicit notice is shown and the stored result is unchanged. This is a byte bound, not a tokenizer-specific token budget.

Artifact references are references only. Host scratch and Docker guest files are deleted during cleanup. Host-mode durable workspace files remain accessible. Docker scopes now capture a bounded workspace text patch before disposal; other findings must still be emitted as captured command output, not promised as durable guest files.

**Automatic patch capture:** `patch.status` is `captured`, `no-change`, `error`, or `unavailable`. Captured results carry a source revision, owned blob reference, exact file/line statistics, and at most 20 preview filenames. The complete patch is an appended `workspace.patch` item in existing `scope inspect/read` evidence. Capture/storage failure marks the scope failed, except cancellation stays cancelled; cleanup still runs. No captured blob is published for an oversized/incomplete patch. Destruction/cancellation may make capture unavailable. No automatic application or promotion.

Before export, a bounded guest listing (100,000 non-directory paths / 8 MiB) is filtered against the original host checkout's ignore rules for new files only. Ignored dependencies, including their symlinks, never enter the archive; tracked paths cannot be hidden by ignores. The archive must match the selected file set exactly. The final guest archive is parsed in memory, never extracted onto the host: strict ustar, checksums/end markers/duplicate paths validated; symlinks, hardlinks, special files, extended headers and `.git` are rejected. Archive transport is limited to 20 MiB and 15 seconds, with at most 20,000 total entries, 10,000 regular files and 12 MiB file content. Paths currently support only ASCII letters/digits and `_./-` with no absolute/traversal components. Changed content must be UTF-8 without NUL. Add/delete/modify/executable-bit changes are retained; empty directories are not Git changes. New files ignored by the original checkout's Git ignore rules (including local info/exclude, not global excludes) are omitted; tracked changes are never omitted. Ignore-check errors fail capture; that subprocess also has a 2 MiB output cap and 15-second deadline, so very large ignored-path listings can explicitly fail below the archive cap. Ignore rules come from the original checkout at capture time, not guest edits; concurrent owner changes can therefore affect new-file selection.

A linear single-hunk-per-file diff avoids unbounded edit-distance work but may include unchanged lines between distant edits. Limit: 200,000 combined old/new newline characters per changed file and a 4 MiB complete UTF-8 patch. Limits fail explicitly rather than truncate. Guest-generated content remains untrusted; background writers can race archive capture and guest programs can misreport data. Capture is not an atomic/forensic snapshot or independent verification of correctness.

## Bounded evidence retrieval

The existing `scope` tool supports:

- `inspect` without a scope ID: ten child scopes per page, with clipped goals and evidence calls. Optional `page` defaults to 1. `/scope tree [page]` provides the human equivalent.
- `inspect` with `scopeId`: clipped capsule summary and ten numbered work-tool calls per page. Labels use literal arguments/output excerpts, never model-generated conclusions. `scope_return` and assistant messages/thinking are excluded.
- `read` with `scopeId` and positive integer `item`: recorded arguments and result, paginated in chunks of at most 6,000 UTF-8 bytes, without splitting a Unicode code point. Each page repeats the tool, timestamp and a short call preview. Optional `page` defaults to 1. Responses include explicit end/continuation markers and ready-to-use calls; evidence list responses do likewise.

Retrieval pages are bounded to 8 KiB for supported scope/tool records. Capsule delivery keeps its separate 16,000-byte limit, including the new evidence-inspection footer. Evidence numbers are 1-based tool-call occurrences and remain stable as later trace events are appended. Sequentially reused provider call IDs are paired by occurrence rather than replacing earlier results. Missing or overlapping IDs are marked ambiguous and their outputs are not attributed; no FIFO ordering is guessed.

Only scopes in the current parent's store are accessible; identifiers are not arbitrary filesystem paths. Retrieval never executes commands, starts another model, resumes a child, or imports its whole conversation. Output is historical, untrusted data and may no longer describe the current workspace. A tool's recorded error/returned flag is not independent verification of task correctness. Missing completion, missing scope/item, and unavailable full output are distinguished; no evidence is invented.

Where the trace recorder previously retained a full-output blob, retrieval can use it after scratch cleanup. Only same-session/same-scope blob references are followed; arbitrary original `fullOutputPath` values are never opened. Missing or unreadable retained blobs fall back to the recorded excerpt with an explicit notice. Other deleted scratch artifacts and non-text output are not recovered. Secret redaction remains unsupported.

The prototype reuses the full in-memory trace reader (and reads retained text blobs in memory). Response size is bounded; local loading memory/I/O is not. A streaming index is deferred until measured trace sizes warrant it.

## Evaluation rule

The first comparison keeps model, thinking level, prompt, starting repository commit, and available work tools constant. The treatment permits at most one child scope per task (the experiment must enforce this; the extension only limits concurrent children). Reported costs and any spending guidance cover parent plus child, not the parent alone. Evaluate task resolution and output quality against best-effort dollar estimates; retain uncached input, cached input, and output counts when pricing is unavailable. Dollar thresholds are soft guidance unless a hard cap is explicitly declared; future checks do not use cumulative-token cutoffs. Context retention and cache reuse are valuable diagnostics, not substitutes for correctness.
