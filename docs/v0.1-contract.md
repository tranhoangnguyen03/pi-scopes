# pi-scopes experimental v0.1 contract

Status: implementation contract for the first research prototype.

Pi dependency: `@earendil-works/pi-coding-agent@0.85.1`.

Parent and child sessions run in the same process. Goals use the SDK prompt API, results use the local `scope_return` callback, and cancellation uses an abort signal; no socket transport or intercom dependency is required.

Supported hosts: Linux and macOS.

## Purpose

v0.1 tests one claim: a same-model child with isolated conversation context can do noisy investigation and return a bounded result capsule that helps the parent finish a task.

It does not test sandbox security, parallel delegation, recursive delegation, specialist models, worktree isolation, or checkpoint recovery.

## Observable behavior

1. When unused, the extension does not alter the active Pi tool set, model, thinking level, workspace, or conversation.
2. The model can fork one foreground child with `scope({ action: "fork", goal, maxTurns? })`. The goal must be self-contained: concrete question/reproduction, constraints, and expected evidence. The child does not see the parent conversation.
3. The child inherits the parent's model and thinking level but receives a new in-memory session and a hermetic resource loader.
4. The child sees only the explicitly selected built-in tools plus `scope_return`.
5. The child runs in the parent's workspace. This mode is named `host-shared` and makes no read-only or sandbox claim.
6. Each child receives a private scratch directory and scope environment variables.
7. The child must normally finish by calling `scope_return` with a structured result capsule and outcome `complete` or `partial`. Partial means the investigation is incomplete, not that structured return failed.
8. If the child ends without `scope_return`, the harness returns a partial capsule containing its final text and an explicit fallback reason.
9. The parent receives the capsule, including supplied evidence, artifact references, decisions, and confidence, not the child transcript.
10. The full child event trace remains on local disk and can be inspected with `/scope open`, `/scope result`, and `/scope traces`.
11. Cancelling the parent tool call aborts the child session and marks the scope cancelled.
12. Completed scope records remain inspectable after their runtime and scratch resources are disposed.

## Limits

- Maximum depth: 1.
- Maximum active children: 1.
- Execution: foreground only.
- Workspace: host-shared.
- Investigation allowance: `maxTurns` is an integer from 1 to 50, default 8. At the completed-turn boundary the harness stops investigation and, if not externally cancelled, prompts the same child with only `scope_return` enabled. At most two return turns are allowed, including any validation repair. Attempts to call work tools in this phase do not execute them. The default is provisional, not benchmark-tuned.
- A turn includes an assistant response and its tool calls; multiple commands and large outputs can occur in one turn. This is not a tool-call, token, or cost cap. Provider retry/compaction work is not an investigation turn. Combined usage still includes return inference. Parent budget is not automatically reserved.
- Scope limits: the total wall-clock timeout includes both phases and signals cancellation; it is not a process-kill deadline for uncooperative setup or I/O. Parent cancellation or timeout prevents further return prompting and may leave no useful summary. Token and cost usage are measured but not pre-emptively enforced.
- Child usage is returned as Pi-native nested tool usage and included in parent session totals. It counts persisted assistant history, compaction/branch-summary calls, and any nested tool usage. Each returned capsule with measured usage retains it in `usage` (Pi's `Usage` fields plus `turns`).
- The child does not inherit parent permission extensions or repository context files; its host `bash` is unrestricted.
- Trace storage: local plaintext with owner-only directory permissions. Secret redaction is not promised in v0.1.
- Session replacement (`/new`, `/resume`, `/fork`), `/reload`, and shutdown cancel any active child. Completed scopes remain in the trace store.
- Crash recovery: a child still marked active when its host session is reopened is finalized as failed; v0.1 never resumes an orphan runtime.

## Terminal scope states

- `completed`: a valid `scope_return` capsule was captured.
- `partial`: the child explicitly returned incomplete findings, or finished without a valid capsule but recoverable output exists. Only fallback output has a `fallbackReason`.
- `failed`: creation, execution, trace persistence, or capsule validation failed.
- `cancelled`: an abort signal stopped the child.

Runtime disposal is recorded separately and is not a scope state.

## Result capsule

The required fields are:

- `status`: `completed`, `partial`, `failed`, or `cancelled`;
- `summary`: at most 8,000 characters;
- `traceRef`: assigned by the harness.

Optional semantic fields are conclusions, evidence, artifacts, decisions, unresolved questions, and confidence. The harness validates these fields but never invents missing findings.

The combined semantic fields must fit within **16,000 UTF-8 bytes** when serialized as compact JSON (excluding the `outcome` control field and harness metadata). Oversized structured returns are rejected with an instruction to shorten and retry; findings are not silently dropped to satisfy the aggregate limit.

Parent-facing and `/scope result` text is also capped at **16,000 UTF-8 bytes**, including its trace reference. Formatting overhead, legacy results, or fallback text may require display truncation; an explicit notice is shown and the stored result is unchanged. This is a byte bound, not a tokenizer-specific token budget.

Artifact references are references only. Files in the private scratch directory are deleted during cleanup; use durable workspace paths for artifacts the parent must inspect.

## Bounded evidence retrieval

The existing `scope` tool supports:

- `inspect` without a scope ID: ten child scopes per page, with clipped goals and evidence calls. Optional `page` defaults to 1. `/scope tree [page]` provides the human equivalent.
- `inspect` with `scopeId`: clipped capsule summary and ten numbered work-tool calls per page. Labels use literal arguments/output excerpts, never model-generated conclusions. `scope_return` and assistant messages/thinking are excluded.
- `read` with `scopeId` and positive integer `item`: recorded arguments and result, paginated in chunks of at most 6,000 UTF-8 bytes, without splitting a Unicode code point. Each page repeats the tool, timestamp and a short call preview. Optional `page` defaults to 1. Responses include explicit end/continuation markers and ready-to-use calls; evidence list responses do likewise.

Retrieval pages are bounded to 8 KiB for supported scope/tool records. Capsule delivery keeps its separate 16,000-byte limit, including the new evidence-inspection footer. Evidence numbers are 1-based tool-call occurrences and remain stable as later trace events are appended. Sequentially reused provider call IDs are paired by occurrence rather than replacing earlier results. Missing or overlapping IDs are marked ambiguous and their outputs are not attributed; no FIFO ordering is guessed.

Only scopes in the current parent's store are accessible; identifiers are not arbitrary filesystem paths. Retrieval never executes commands, starts another model, resumes a child, or imports its whole conversation. Output is historical, untrusted data and may no longer describe the current workspace. A tool's recorded error/returned flag is not independent verification of task correctness. Missing completion, missing scope/item, and unavailable full output are distinguished; no evidence is invented.

Where the trace recorder previously retained a full-output blob, retrieval can use it after scratch cleanup. Only same-session/same-scope blob references are followed; arbitrary original `fullOutputPath` values are never opened. Missing or unreadable retained blobs fall back to the recorded excerpt with an explicit notice. Other deleted scratch artifacts and non-text output are not recovered. Secret redaction remains unsupported.

The prototype reuses the full in-memory trace reader (and reads retained text blobs in memory). Response size is bounded; local loading memory/I/O is not. A streaming index is deferred until measured trace sizes warrant it.

## Evaluation rule

The first comparison keeps model, thinking level, prompt, starting repository commit, and available work tools constant. The treatment permits at most one child scope per task (the experiment must enforce this; the extension only limits concurrent children). Reported costs and any spending guidance cover parent plus child, not the parent alone. Evaluate task resolution and output quality against best-effort dollar estimates; retain uncached input, cached input, and output counts when pricing is unavailable. Dollar thresholds are soft guidance unless a hard cap is explicitly declared; future checks do not use cumulative-token cutoffs. Context retention and cache reuse are valuable diagnostics, not substitutes for correctness.
