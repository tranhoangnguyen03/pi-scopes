# Context modes implementation plan

Approved API: scope run with context fresh (default) or fork. Remove model-facing action fork, without an alias. Keep inspect/read. Historical evaluations remain unchanged.

Fork snapshots only the active parent branch before the assistant message containing the current run call, plus the effective system prompt. This avoids inheriting incomplete tool calls. The child has its own session, fixed tools and child instructions; inherited permissions/extensions are not claimed. Count only newly generated child usage, including return and compaction, not historical inference copied into its context.

Fresh loads project guidance by default; repoInstructions:false opts out for fresh only. Use Pi's documented filename precedence but restrict discovery to repository-root → cwd, or cwd alone without Git. Reject unreadable, outside-root symlink, or oversized selected guidance before inference; do not silently truncate. Nested directories explored later require checking their local guidance. Fork reuses inherited instructions instead of rediscovering them.

Steps: tests first for branch snapshot/accounting and fresh/fork visibility; add narrow guidance helper and tests; implement run/context plumbing and metadata; update current docs/tests (not historical artifacts); run npm test, npm run check and git diff --check. The implementation slice introduced no paid model tests, dependencies, consent gate, sandbox or commits. The owner subsequently approved the small GLM usability check and Git checkpoint described below.

Implemented and verified locally: 54 tests pass, TypeScript and diff checks pass. Real-SDK scripted-provider tests cover fresh/fork parent-marker visibility, invocation-call exclusion, no child transcript pollution, historical assistant/compaction usage exclusion, nonduplicated inherited/child instructions, bounded return in both modes, guidance defaults/opt-out/global exclusion and failure before inference. A static AGY review found no isolation/accounting blocker and identified duplicated fork assignment instructions; a failing regression confirmed it and the duplication was removed. Its suggestion to support string-valued assistant content was not adopted: Pi's canonical AssistantMessage content is an array; corrupt session data is not silently repaired.

September 7 follow-through: the [two-case GLM usability check](../../evals/results/2026-09-07-glm-context-modes.md) returned correct answers and selected the expected fresh/fork modes for $0.00119 combined estimate. No implementation changes were needed. Because the fork goal restated the background, the check does not establish a causal benefit from inheritance. Preserve this milestone in Git; next design target is enforced execution isolation, not further API expansion.
